# 07 · VIP 会员与变现

> 当前阶段可变现很轻：先做产品；**广告**与 VIP 后置。人工批改用微信收费亦可。

## 0. 变现优先级（按最新需求）

| 顺序 | 方式 | 说明 |
|------|------|------|
| 1 | 刷题流量主广告 | 微信小程序流量主（有门槛）；免费用户展示 |
| 2 | AI 批改按次 | 你出 Token，用户买次数 |
| 3 | 人工批改按篇 | 工单 + 加微信交付，客单价更高 |
| 4 | 会员去广告 / 解锁题量 | 有用户量后再做 |

核心模型（付费批改）：**用户付钱给你 → 你开通次数/人工工单；AI 成本从差价覆盖。**

## 1. 权益设计（建议首版）

| 权益码 | 含义 | 免费用户 | VIP |
|--------|------|----------|-----|
| `content_vip` | 备考全文/解析 | 仅试看 | ✓ |
| `school_advanced` | 热度趋势/对比高级 | 基础列表 | ✓ |
| `ai_essay_quota` | 批改次数 | 赠送少量 | 每月赠额 |
| `consult_discount` | 1v1 优惠券 | 无 | 可选 |

权益存在「用户权益账本」，不要只写一个 `is_vip` 布尔值（后期难扩展）。

## 2. 商品 SKU 示例

| SKU | 价格示意 | 开通动作 |
|-----|----------|----------|
| VIP 月卡 | ¥49～99 | VIP 30 天 + AI 20 次 |
| VIP 季卡 | ¥129～199 | VIP 90 天 + AI 80 次 |
| AI 次卡 10 次 | ¥19～30 | 仅加次数 |
| AI 次卡 50 次 | ¥79～99 | 仅加次数 |

具体价你按竞品与成本表再定；上线前用 06 文档的次均成本算毛利。

## 3. 开通权限的三条通道

### A. 微信支付（主路径）

```
小程序下单 → 服务端统一下单 → 用户支付
  → 微信回调 notify
  → 验签、幂等
  → 写 order=paid
  → 写 entitlement（VIP 到期时间）
  → 增加 ai_quota
  → 小程序查单展示成功
```

注意：回调与客户端查单都要**幂等**，防止重复加次数。

### B. 权益兑换码（运营/分销）

```
后台生成码（批次、绑定 SKU、次数上限、过期时间）
  → 用户在「权益兑换」输入
  → 核销成功 → 与支付相同的开通逻辑
  → 码作废
```

适合：社群卖卡、代理、活动赠送、支付未开通时的客服补单。

### C. 客服手动开通（后台）

订单纠纷、对公转账、线下收款时，管理员输入 `userId + SKU` 开通，必须写操作日志。

## 4. 和「我的 / 权益兑换」页面的关系

| 入口 | 作用 |
|------|------|
| 我的 → VIP 条 | 展示到期日、剩余次数、去开通 |
| 我的 → 权益兑换 | 卡密核销（对标参考图） |
| 首页宫格 → 权益兑换 | 同页 |
| AI 批改页 | 次数为 0 时强引导购买 |
| 内容详情 | VIP 锁与购买按钮 |

## 5. 账本表逻辑（概念）

- `orders`：支付单
- `redeem_codes`：兑换码
- `user_entitlements`：某用户某权益的生效区间
- `user_quotas`：可消耗次数（AI）
- `quota_ledger`：每次加减流水（审计、防扯皮）

到期：定时任务或请求时判断 `expire_at < now` 则视为无 VIP；次数与 VIP 解耦（VIP 过期但剩余次卡仍可用——推荐这样，减少客诉）。

## 6. 合规与微信侧注意

- 虚拟支付走微信支付；不要引导「加微信转账」作为主路径（易被投诉/封）
- 清晰展示：非教材出版社官方、成绩无保证
- AI 结果加免责声明：「辅助学习，不代表阅卷标准」
- 备好用户协议、隐私政策、退款规则（虚拟商品是否可退写清楚）

## 7. 变现路径小结

```
内容免费引流（院校库 + 部分基础内容）
    → AI 试用 1～3 次 / 真题目录曝光
    → 付费 VIP 或次卡
    → 高客单：1v1 择校咨询（人工）
    → 复购：次卡、续费月卡、新一季真题包
```

你的 Token 成本是 COGS（销货成本）；控制「日上限 + 缓存重复提交 + 便宜模型」就能稳住毛利。
