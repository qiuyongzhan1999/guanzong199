# 06 · AI 批改与 Token 成本

目标：你用**全网尽量便宜的大模型 API**做批改，用户买你的 VIP/次数；你赚差价。

## 1. 原则

1. **API Key 只在服务端**，小程序永远不直连大模型。
2. 用户消耗的是你业务侧的「批改次数」，不是大模型原始 Token。
3. 每次批改：校验登录 → 校验剩余次数 → 调用模型 → 成功再扣次 → 存记录。
4. Prompt 固定成「管综写作评分标准」，输出强制 JSON，便于展示和质检。

## 2. 模型怎么选（便宜优先）

价格经常变，以各官网实时标价为准。选购策略：

| 优先级 | 类型 | 典型选择 | 适用 |
|--------|------|----------|------|
| 首选试跑 | 低价 Flash / Lite | **DeepSeek Chat/Flash 档**、**豆包 Lite**、通义 Qwen Flash | 日常批改 |
| 质量不够再升 | 中档 | DeepSeek 正式版、Qwen-Plus | 差评多时 A/B |
| 一般不用 | 旗舰 Max/Pro | 贵，首版别用 | 个别高价人工复核产品 |

**实操建议（2026）：**

1. 注册 **DeepSeek** 与 **豆包** 各一个，用同一批作文测质量与单价。
2. 谁「有效批改成本更低」（单价 × 实际消耗 Token，且分数靠谱）就定为主；另一个做兜底。
3. 系统 Prompt + 评分 Rubric 较长时，优先选支持 **上下文缓存** 的模型，重复前缀会更省。

> 「全网最便宜」会变动；文档不写死单价。你在后台加一个 `ai_provider` 配置，随时切换，避免绑死一家。

## 3. 单次批改成本怎么估

假设：

- 系统 Prompt + 评分标准 ≈ 1500 tokens（可缓存）
- 学生作文 ≈ 800～1200 汉字 ≈ 1000～1500 tokens
- 模型输出点评 ≈ 800～1200 tokens

粗算单次总消耗约 **3k～5k tokens**。用 Flash/Lite 档时，单次成本通常可压到 **几分钱量级**（以当时标价为准）。  
对用户售价建议：**单次 1～3 元** 或 **VIP 包月含 N 次**，保证毛利。

## 4. 配额与产品包装（推荐）

| 商品形态 | 权益 | 说明 |
|----------|------|------|
| 新用户赠送 | 1～3 次 | 促体验，防刷要绑微信 |
| 次卡 | 10 / 30 / 50 次 | 纯 AI 用户 |
| 月卡 VIP | 内容全开 + 每月 20 次批改 | 超次可再买次卡 |
| 季卡/年卡 | 次数更高或每日上限 | 设**每日上限**防亏损 |

**不建议**首版做「无限次批改」，除非单价极低且有严格日封顶。

## 5. 服务端流程（必须按此实现）

```
1. 用户提交 essay_type + content
2. 校验长度（如 200～2000 字）、登录态
3. BEGIN 事务：读 user_quota（行锁）
4. 若 remaining <= 0 → 返回需购买
5. 调 LLM（超时、重试策略）
6. 成功：remaining - 1，写 essay_job + essay_result
7. 失败：不扣次（或仅超时已产生账单时记成本审计），返回可重试
8. COMMIT
```

附加：

- `content_hash` 相同且 N 小时内：直接返回历史结果，不扣次或扣 0
- IP/用户维度：每分钟 ≤ 2 次，每天 ≤ 配置上限
- 审计表记录：provider、model、prompt_tokens、completion_tokens、cost_estimate

## 6. Prompt 结构（草稿）

```
你是考研管理类联考写作阅卷助手。
题型：{{论证有效性分析|论说文}}
请按以下维度打分并给修改建议：……（你的 Rubric）
只输出 JSON，字段：
overall_score, dimensions[{name,score,comment}],
strengths[], issues[{quote,problem,suggestion}],
revised_outline, summary
```

Rubric 放你自己的教研标准，这是质量壁垒，比换模型更重要。
